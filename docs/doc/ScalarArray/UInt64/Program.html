    In-place programs on UInt64Array #

    UInt64Array.InPlace n α is a program that reads and writes an array of size n in place and returns a value of type α. It is a monad, and programs are built from:

    • read i h, readThen i h k, write i h v and writeThen i h v k, at a USize index i with its bound h (toNat_add_lt_of_window gives the bound of off + j in a window);
    • InPlace.ite and InPlace.dite, which branch inside one program;
    • the loops forIn lo hi and forInRev lo hi, which run a body for each j from lo up to hi - 1, or from hi - 1 down to lo, threading an accumulator. The body gets both bounds of j, lo.toNat ≤ j.toNat and j.toNat < hi.toNat. forIn2 and forInRev2 thread two accumulators as separate arguments, so that scalars such as carries stay unboxed;
    • forInBind, forIn2Bind, forInRevBind and forInRev2Bind, a loop followed by the rest of the program, which the loop calls itself, so that its last accumulators reach the rest unboxed.

    A program runs on an array with a.runInPlace m or m.run a h, which make the array exclusive once, before the program runs. runForInThen, runForInRevThen and runForIn2Then run a single loop and hand its last accumulators and the new array to a continuation, without a result pair.

    A tail program InPlace.Tail n γ is a program that ends by handing its result and the new array to a continuation k, which returns a γ, where run would return the pair of them: Tail.done x k ends it, Tail.bind m t runs an in-place program m before it, and Tail.readThen, Tail.writeThen, Tail.ite, Tail.dite and the loops Tail.forInBind, … are those of InPlace. The continuation runs inside the program's last loop, so its last accumulators reach k unboxed, and no result pair is built. A tail program runs with a.runInPlaceThen t, a.runInPlaceThenOf n h t or t.run a h, and on the window of a slice s in its array with s.runInPlaceThenOf n h t.

    InPlace.zipForInFrom, for internal use, is the loop of the two-array updates zipModifyStride: it threads two states, one for each array.

    Tail programs also have loops in continuation-passing style, Tail.forIn lo hi init body k and Tail.forInRev, with up to four variables in Tail.forIn2, Tail.forIn3, Tail.forIn4, and so on. Their body is itself a tail program, which ends by calling a continuation next on the next variables, and the loop ends with k. Each variable is an argument of the loop, so scalars stay unboxed, and a nested loop, whose k calls the outer next, compiles to mutually recursive loops with no allocation. They are specified by their one-step equations (Tail.forInFrom_eq, …).

    The array is never visible to a program: InPlace and its state have private constructors, so the only code that touches the state is the code in this module, which passes it on linearly. That is what lets write store without checking that the array is exclusive. The in-place folds of ScalarArray.UInt64.InPlace are programs of this kind, and the experimental notation inplace a do … of ScalarArray.Notation writes programs of this kind.

    The loops must be the loops of this module. A program that calls itself recursively compiles to a closure for each step, and for in do notation boxes its mutable variables at each step, so both are much slower than forIn, whose step is inlined into one loop with unboxed accumulators. Likewise, if c then t else e on programs builds both branches as closures, where InPlace.ite branches inside the program.

    Programs are specified by InPlace.run, whose behavior the run_* lemmas give. Each loop has a one-step equation (forInFrom_eq, forInRevFrom_eq, …), and each Bind loop and runFor*Then an _eq lemma in terms of the plain loop. bind_eq and pure_eq turn InPlace.bind and InPlace.pure, which the notation writes, into >>= and pure.
