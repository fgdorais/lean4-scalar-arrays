    Notation for in-place programs #

    The root module ScalarArray doesn't import this one, because it makes inplace a keyword. Outside of inplace … do blocks it adds nothing else: no other keyword, and no other term. The statements are parsed only in a block, the terms of the expansion aren't terms that can be written, and inplace_bound, the tactic that proves the bounds of indices, isn't a keyword.

    inplace a do … writes an in-place program (XArray.InPlace) on the array a in a small imperative language, and runs it, which returns the program's result and the new array, or hands them to a continuation then k. It works for all 13 array types, and for their slices (see Slices):

    inplace a do
  for j in 0...len with (c := 0) (b := 0) do
    let u := a[xs + j]
    let v := a[ys + j]
    let (s, c') := addc u v c
    let (d, b') := subb u v b
    a[xs + j] := s
    a[ts + j] := d
    c := c'
    b := b'
  return (c, b)

    Statements #

    • a[i] in the terms of a statement reads the current element at the USize index i, before the statement runs: let x := a[i] reads it into x, and a[i] := a[i] + 1 increments it. So a read can't be under a binder, or in a branch of a term (if, match, or the right side of &&, ||, ∧ and ∨), which would run later or not at all: read it first with let x := a[i], or branch with an if statement.
    • a[i] := e writes e at i.
    • let x ← m runs an in-place program m : XArray.InPlace n α, for the program's size n, and binds its result, so that programs compose.
    • let p := e binds a pure value, where p can be a pattern such as (s, c), and let x : t := e one of type t.
    • let mut x := e or let mut x : t := e declares a mutable variable, and x := e assigns it, or (x, y) := e for a pattern of mutable variables. As in do notation, a let can't shadow a mutable variable.
    • have h : t := p adds a fact to the context, for the bounds of later indices. As in terms, h defaults to this and t to the type of p: have : t := p, have h := p.
    • if c then … else … and if h : c then … else … run one of two blocks, which may read, write, loop and assign mutable variables. The else block is optional, and unless c do … is if ¬c then ….
    • if let p := e then … else … runs the first block, with the variables of the pattern p, if e matches it, and the second one, which is optional, otherwise.
    • match e with | p => … | q => … runs the block of the first pattern that e matches, and match e, f with | p, q => … matches several terms.
    • for j in lo...hi do … loops over lo ≤ j < hi upward, and for j in reverse lo...hi do … over the same range downward, from hi - 1 to lo. The bounds are USizes, and the ranges are those of core: lo...hi and lo...<hi, lo...=hi (up to hi), lo<...hi and lo<...=hi (from lo + 1), and *...hi and *...=hi (from 0). lo.toNat ≤ j.toNat and j.toNat < hi.toNat are in context in the body, or j.toNat ≤ hi.toNat and lo.toNat < j.toNat for the other ranges, which need hi.toNat + 1 < USize.size and lo.toNat + 1 < USize.size, proved like the bounds of indices. A bound that is a literal, as in 0...4, is in context as a Nat literal too, j.toNat < 4, which proofs such as get_elem_tactic use. for h : j in lo...hi do … names the bounds, h : lo.toNat ≤ j.toNat ∧ j.toNat < hi.toNat, or the bounds of the other ranges (only the upper one for *...hi). for j in lo...hi by s do … runs over lo, lo + s, … below hi, for s > 0, and reverse runs over the same indices downward.
    • An optional with (x := init) … clause names the loop's variables, as (x : t := init) with their types: up to four, which the loop keeps as separate unboxed arguments. They are mutable in the body, and they hold their last values after the loop. Loops nest, and a nested loop allocates nothing either.
    • while c do … and while h : c do … loop while c holds, with a with clause like for. The condition runs, with its reads, before each step. A while loop stops after USize.size - 1 steps at the most.
    • break leaves the innermost loop, and its variables keep their current values after it. continue goes on with the loop's next step.
    • return e ends the program with the result e, anywhere, even in a loop, and return with (). Without it, the result is (). Nothing in a block can follow a return, a break or a continue.

    A loop body can assign only its own variables: to update a variable across a loop, carry it, as with (c := c).

    Results #

    inplace a do … returns the pair of the program's result and the new array. With then k after the statements, it is k x a' h instead, for the result x, the new array a' and h : a'.size = a.size:

    inplace a do
  for j in 0...len with (c := 0) (b := 0) do
    …
  return (c, b)
then fun (c, b) a' h => g c b a' h

    The program calls k where it ends, inside its last loop if it ends with one, so the result goes into no pair, and scalars such as the carries above reach k unboxed. h lets k run another program on a' with the bounds proved for a.

    Slices #

    On a slice s of an array (an XArray.Slice), inplace s do … reads and writes the slice's elements, at indices counted from the start of the slice, with bounds i.toNat < s.size, and s.usize is its size as a USize. The program runs on the slice's array in place, with XArray.Slice.runInPlaceThenOf, and returns the new slice, on the new array; with then k, k gets the new slice and h : s'.size = s.size. let x ← m works on arrays only.

    def double (s : UInt32Array.Slice) : UInt32Array.Slice :=
  (inplace s do
    for j in 0...s.usize do
      s[j] := 2 * s[j]).2

    The program reads and writes the array at off + i, where off is the slice's start as a USize. When the array's size is less than USize.size, as it always is at runtime, that is the element i of the slice.

    Proofs #

    A program is defined by its expansion, which runInPlaceThenOf_eq and the run lemmas of XArray.InPlace.Tail take apart (ScalarArrayTest/Notation.lean has these examples):

    • A program without branches or loops: simp [XArray.runInPlaceThenOf_eq] runs it.
    • An if: simp only [XArray.runInPlaceThenOf_eq, XArray.InPlace.Tail.run_readThen, XArray.InPlace.Tail.ite_eq] lifts it out of the program, and the cases follow, for example by by_cases hc : c <;> simp [hc].
    • A loop: after XArray.InPlace.Tail.forIn_eq, Tail.run_forInFrom runs the loop as iterRange f lo hi of a function f of the step, the loop's variables and the array, for a step that hbody proves. iterRange_prod_of_snd drops the array when the loop only reads. Tail.run_forInFrom_modify and Tail.run_forInFrom_write run the loops that write a[e j] := …, as modifyAt, and Tail.run_forInRevFrom and its forms the loops down.

    How the notation expands may change in later versions, so proofs that take a program apart may need adjusting after an upgrade.

    Compilation #

    The program expands to a tail program (XArray.InPlace.Tail) on arrays of size n, run with a.runInPlaceThenOf n h, where n and a.usize are bound to variables before the program runs, and the program uses them in place of a.size and a.usize. So nothing in the compiled program refers to a, which the compiler would otherwise keep alive past the point where the program makes the array exclusive, and the array would be copied. The program ends with Tail.done x k, where k is the then continuation or makes the pair. Its statements expand to the tail programs readThen, writeThen, ite, dite and the loops Tail.forIn, Tail.forIn2, … and Tail.forInRev, …, in continuation-passing style: a loop body ends by calling next on the loop's variables, which runs the next step, and the loop ends by calling the rest of the program, so the variables are arguments of both and stay unboxed. continue calls next, and break calls the rest of the program, which a loop that breaks binds to a local function. A nested loop ends by calling the outer loop's next, so the two compile to mutually recursive loops with no allocation, and the program compiles to the same loops as a hand-written one. The rest of the program after an if becomes a local function of the mutable variables, which the compiler turns into a join point: an if in a loop allocates nothing.

    Bounds #

    The bound of each index is proved by the tactic inplace_bound, from the hypotheses in context:

    • for an index off + j in a loop over j < len, from a window hypothesis off.toNat + len.toNat ≤ a.size (tried only on indices that are sums, so that other indices don't pay for it);
    • otherwise by lia;
    • otherwise, for indices with USize arithmetic such as j - 17 or 2 * j + 1, by grind, which splits on the platform width System.Platform.numBits (see the grind_pattern in ScalarArray.Internal), so the proof holds on both widths.

    It looks inside conjunctions. A loop body has both bounds of its index, lo.toNat ≤ j.toNat and j.toNat < hi.toNat, in context, and the program has a.usize.toNat ≤ a.size, so a.usize works as a loop bound with no other hypothesis. A bound that needs more is given by a have before the index, or by a hypothesis around the program, and a bound that inplace_bound can't prove is reported with its goal. For example, in this left shift of 64-bit limbs by 1111 bits:

    if h : 18 ≤ a.size then
  (inplace a do
    for j in reverse 18...a.usize do
      a[j] := (a[j - 17] <<< 23) ||| (a[j - 18] >>> 41)
    a[17] := a[0] <<< 23
    for j in 0...17 do
      a[j] := 0).2
else UInt64Array.mk (Array.replicate a.size 0)

    Limits #

    • a is a local variable: the program's array or slice. b[i] := e on another array b is an error, while b[i] in a term is ordinary indexing of b, with its own bound.
    • Inside the program, a is the array before the program runs, so it is an error outside of the reads a[i] and its size a.size or a.usize: a[i]!, a[i]'h or a.toArray would read old elements, and keep the old array alive, which copies it. A have and the proofs in by blocks may use a, and so may then k, which runs after the program, but k keeps the old array alive if it uses more than its size.
    • Reads are written a[i], not ← a[i]: ← runs a program.
    • A loop has at most four variables.
    • A block has at least one statement.
    • A program makes the array exclusive before it runs, even when it only reads, so a shared array is copied. For a computation that only reads, use plain reads a[i], foldl or the folds of slices, which don't copy.
    • There is no x += e, and a term such as pure x is no statement: both are errors that say what to write instead.
